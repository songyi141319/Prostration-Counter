# 智能姿态序列引擎(Pose Sequence Engine)设计

日期:2026-06-12
状态:已与用户确认
前置:`2026-06-11-kowtow-night-robustness-v3-design.md`(经典引擎 v3,保留为可切换选项)

## 1. 背景与问题

实测发现经典引擎(`kowtowDetection.ts` v3)在「完整礼拜」模式下存在两类误计:

1. **安置误计**:点「开始计数」后弯腰把手机放到地上,手刚拿开就记了 2 次。
   根因:无"开始后安置期"概念。摆放期间画面剧烈晃动产生的渐变位移逃过单帧跳变滤波
   (`JUMP_REJECT_THRESHOLD` 只挡瞬移),撑大幅度后武装周期;手遮挡触发「消失即到底」
   (门槛还按 `OCCLUSION_DROP_RATIO` 减半);手拿开后人入画被判"回正"→ 第 1 计;
   画面继续稳定的过程又凑出假周期 → 第 2 计。`MIN_CYCLE_MS=600ms` 拦不住全程数秒的摆放动作。
2. **弯腰误计**:单独弯腰问讯(70–90°)在「完整礼拜」模式下被计数。
   根因:引擎只看一维信号 bodyY(头部加权 Y)。状态机各阶段(bow/kneel/bottom)只是同一信号的
   不同深度阈值,连续下降动作天然顺序穿过全部阈值,序列验证形同虚设。近距离正拍时,深弯腰的
   头部下移轻松超过 `ritualDropKFront=1.1` 倍肩宽;头出画还触发减半门槛的「消失即到底」。

共同根本缺陷:**一维深度信号无法表达"身体经历了什么姿态构型"**。

## 2. 目标与原则

- 新建独立的**智能姿态序列引擎**,与经典引擎**自由切换**;经典引擎代码不动,作为兜底。
- **宁漏勿误**:只有明确验证到完整序列(或满足补计条件)才计数;不确定就不计。
- **前缀补计**:磕头阶段是失焦高发段。已确认强前缀(站立→弯腰→下跪迹象)后失焦,
  随后重新检测到稳定站立 → 补计 1 次。
- **防双计(周期唯一出口)**:一次大拜在任何路径组合下恰好计 1 次,由状态机结构保证。
- 两种摆放方式都支持:全身可见(严格直接观测)与仅上半身(推断模式),自动判别。

## 3. 用户动作序列(领域事实)

完整礼拜(汉传大拜)实测流程,摄像头视角可观测序列:

```
站立合掌(3–5s)→ 问讯弯腰(70–90°)→ 回直(短暂)→ 徐徐下蹲、双膝跪地
→ 展手、头额触地(失焦高发段)→ 翻掌停留 → 起身回站立
```

单独问讯(需拒计):站立 → 弯腰 → 回直站立,**从不出现整体下沉**。

关键几何事实(用户纠正确认):弯腰 70–90° 时肩部绕髋旋转,高度降至接近髋部
(约站立身高 50–60%),可能比跪直时的肩还低。**肩部高度单独不可作为弯腰/下跪的区分维度**。

## 4. 架构

新文件 `src/components/poseSequenceEngine.ts`,纯函数 reducer,接口与经典引擎对齐:

```
advancePoseSequence(prevState, landmarks, now, params)
  → { state, counted, backfilled, debug }
```

内部三层:

```
MediaPipe 33 关键点
  → 特征提取器(每帧多维特征)
  → 姿态分类器(每帧:站立/弯腰/跪姿/趴底/过渡中/不可见,带防抖)
  → 序列验证状态机(带时长约束、安置期、挂起补计、唯一出口)
```

`KowtowCounter.tsx` 增加引擎选择状态 `engine: 'smart' | 'classic'`(默认 smart),
主界面可切换;智能引擎运行时显示当前识别阶段名。

## 5. 特征提取(每帧 FrameFeatures)

| 特征 | 来源 | 用途 |
|---|---|---|
| headY | 头部 5 点加权(沿用现有 computeBodySignal 思路) | 头部高度 |
| shoulderY | 双肩(11/12)中点,可见性达标时 | 肩部高度 |
| hipY | 双髋(23/24)中点,可见性达标时(近拍站立常为 null) | 整体下沉判定 |
| kneeVisible / kneeY | 膝(25/26) | 全身视野直接判跪 |
| headShoulderGap | shoulderY − headY(正=头在肩上方) | 前倾/竖直形态判别核心 |
| shoulderWidth | 双肩 x 距离 | 尺度参照(沿用) |
| visibility 签名 | 头/肩/髋/膝 各组可见位 | 消失签名:自顶向下顺序消失=趴底;同时全失=遮挡/出画 |

所有特征 null 安全;沿用 v3 的单帧跳变滤波与肩宽突变剔除作为输入清洗层。

## 6. 姿态分类器

每帧规则打分输出 `PoseLabel`,连续 N 帧一致才确认(防抖):

- **STANDING(站立)**:竖直形态(headShoulderGap 为正常站立值域),headY 在站立基线带内。
- **BOWING(弯腰/前倾)**:**前倾形态** —— headShoulderGap 压缩至接近 0 或为负
  (头肩重叠/头低于肩,头顶朝镜头);髋(若可见)高度不变。
  降级:近拍深弯腰时头部点(鼻/眼/耳)可能丢失,此时"肩仍可见 + 头部点丢失 + 无整体下沉"
  也作为 BOWING 证据(与趴底签名的区别:肩未消失、未经历 KNEELING)。
- **KNEELING(下蹲/跪)**:**竖直形态 + 整体大幅下沉** —— headShoulderGap 保持正常,
  但头肩整体 Y 相对站立基线下沉超过阈值(以肩宽为尺);髋(若可见)大幅下降;膝(若可见)入画/触地。
- **PROSTRATE(趴底/磕头)**:跪之后再次前倾且头部极低;或符合趴底消失签名
  (头先消失→肩随后消失,且此前已确认 KNEELING)。
- **ABSENT(不可见)**:关键点整体丢失(遮挡/出画),不符合趴底签名。
- **TRANSITION(过渡中)**:不满足任何稳定姿态。

**弯腰 vs 下跪的判别核心**:前倾形态(头肩压缩)= 弯腰;竖直形态 + 整体下沉 = 下跪。
高度维度只作辅助,不单独定性。

## 7. 序列验证状态机(完整礼拜模式)

```
AWAIT_SETUP(安置期) → ARMED(待命) → BOW → KNEEL → BOTTOM → RISE → 计数,回 ARMED
                                      ↓(宽限窗无下沉)
                                    拒计,回 ARMED
        强前缀 + 失焦 → SUSPENDED(挂起) → 稳定站立:补计 1 → ARMED
                                        → 超时 60s:放弃 → AWAIT_SETUP
```

- **安置期 AWAIT_SETUP**:点「开始」后必须连续检测到稳定 STANDING ≥ 2s 才进入 ARMED。
  期间一切信号(晃动、丢失、乱跳)只用于尝试建立站立基线,绝不计数、绝不武装。
  界面提示"请站到画面中,保持站立"。→ 根治问题 1。
- **ARMED → BOW**:确认 BOWING 稳定 ≥ 0.3s,记录证据链。
- **BOW → KNEEL**:允许短暂回直,**宽限窗 ≤ 3s** 内出现 KNEELING(竖直形态整体下沉)→ 继续;
  宽限窗内无下沉且保持站立 → **拒计**(单独问讯),静默回 ARMED。→ 根治问题 2。
- **KNEEL → BOTTOM**:确认 PROSTRATE(直接观测或趴底消失签名)。
- **BOTTOM → RISE → 计数**:重新出现且整体回升,回到站立基线带并稳定 ≥ 0.5s → `finishCycle('completed')`。
- **时长约束**:离开 ARMED 到计数 ≥ 3s(真实大拜 5–10s);BOTTOM 允许长停留(磕长头/祈祷,
  超时倍率沿用 v3 思路);其余阶段超时自动复位防卡死。
- 磕头数(prostration)模式:沿用同一分类器,序列简化为 ARMED → BOTTOM → RISE,细节在实施计划中定。

## 8. 挂起与前缀补计

- **进入条件**:证据链已含强前缀 —— STANDING→BOWING 确认,且 KNEELING 已确认或已出现明确
  下沉迹象;随后 ABSENT/错乱超过正常过渡时长 → 进入 SUSPENDED。
- **挂起期间正常计数路径关闭**(不存在"既正常计数又补计"的通路)。
- **出口仅二**:
  1. 重新检测到稳定 STANDING ≥ 1.5s(比正常计数出口的 0.5s 更严,因为是推断补计)
     → `finishCycle('backfilled')`,计数 +1,UI 标记"+1(补)",该站立时刻归属**新周期**;
  2. 超时 60s 无人 → `finishCycle('abandoned')`,不计,回 AWAIT_SETUP。
- **不补计的情形**:证据链只到 BOWING、无任何下沉迹象就消失(可能弯腰后走开)→ 宁漏勿误。

## 9. 防双计:周期唯一出口原则

- 每轮为一个周期;周期终结**唯一**经由 `finishCycle(reason)`,
  reason ∈ {completed, backfilled, rejected, abandoned}。
- `finishCycle` 立即清空证据链并开启新周期 —— 同一周期结构上不可能产生两次计数。
- 专项单测:磕头失焦 → 重新出现 → 起身 → 站立,断言全程 count 恰好 +1。

## 10. 双视野自适应

- ARMED 建立站立基线时检测髋/膝可见性:可见 → **全身模式**(KNEELING/PROSTRATE 需直接观测,最严格);
  不可见 → **上半身模式**(KNEELING 靠竖直形态整体下沉,PROSTRATE 接受消失签名)。
- 每轮动态判定,无需用户设置。

## 11. UI 变更

- 模式选择旁新增引擎切换:「智能引擎(推荐)」/「经典引擎」,默认智能。
- 智能引擎运行时显示当前识别阶段(站立/弯腰/跪/磕头/起身/挂起)。
- 补计时特殊提示音 + 显示"+1(补)"。
- 安置期显示引导文案。

## 12. 测试策略

纯函数 reducer + vitest,沿用现有 `__tests__/` 风格;合成关键点序列 helper 生成各姿态典型
landmark 布局。必测用例:

1. 标准完整序列(全身/上半身两种视野)→ 计 1。
2. 单独弯腰问讯(含回直)→ 计 0。
3. 安置期乱信号(晃动/遮挡/手拿开)→ 计 0,且不武装。
4. 磕头失焦 → 重新站立 → 补计 1(且恰好 1,防双计专项)。
5. 弯腰后消失、无下沉迹象 → 计 0。
6. 长时间趴底(祈祷)→ 不超时复位,起身后计 1。
7. 挂起超时 60s → 放弃,计 0。

## 13. 错误处理

- 全特征 null 安全;任意阶段超时复位,状态机不会卡死。
- 智能引擎异常不影响经典引擎可用(切换兜底)。
- 引擎选择用组件状态(useState,默认智能引擎),与现有 tuning 行为一致(现有 tuning 亦无持久化);
  持久化留待后续需要时再加(YAGNI)。
