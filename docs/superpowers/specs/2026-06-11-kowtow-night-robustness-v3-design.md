# 大拜计数器 · 夜间鲁棒性 v3 设计

日期：2026-06-11
模块：`src/components/kowtowDetection.ts`
背景：v2 上线后白天表现良好，但夜间漏计严重（30+ 拜只计 20+）。用户观察到
「起身时跟踪点一团挤在头顶，随后才恢复」——低光照下 MediaPipe 输出错乱关键点。

## 根因链

1. **垃圾帧无条件入算**：错乱帧的肩宽塌缩近 0、高度乱跳，直接污染
   `smoothedBodyScale` 与 `standingBodyY` 基线。
2. **基线单向棘轮死锁**：回正判定 = `bodyY ≤ 基线 + 容差×肩宽`。基线被拉高或
   容差带被压窄后，真实预备位永远过不了线 → 卡死在底部阶段；而基线只在
   「READY 且已回正」时更新，永无机会自我修复。
3. **v2 的底部超时 ×5 放大损失**：每次死锁占用最长 30 秒，期间所做的拜全部丢失。

## 设计：三层防线

### 第一层 · 输入合法性过滤（预防污染）
- **跳变滤波**：`|raw − smoothed| > 0.22`（单帧不可能位移）→ 该帧按信号丢失
  处理（走既有软闸门/遮挡路径）；若新位置连续 3 帧自洽（互差 ≤ 0.1）→ 接受为
  真实位置并直接续上（动作断层后的衔接）。
- **肩宽突变剔除**：raw/smoothed 比值 < 0.55 或 > 1.8 → 拒收该帧肩宽；连续 8 帧
  仍是新值才接受（真实距离变化）。
- **肩宽下限**：门槛/容差计算中肩宽取 `max(baselineBodyScale, 0.05)`。

### 第二层 · 周期局部参照（脏基线下仍能计数）
- 新增 `cycleStartBodyY`：armed 且处于预备位时持续快照；离开预备位即冻结。
  这是本周期自己的「顶部参照」，与全局基线解耦。
- 深度门槛 / 到底判定 / 遮挡前置门槛改用 `cycleDrop = cycleMax − cycleStart`
  优先（无快照时回退全局）。
- **比例回正**：`bodyY ≤ cycleMax − 0.7 × drop` 且持续 2 帧（新计数器
  `recoveredFrames`），与绝对回正取或，用于底部→计数转换。
- **时间维度**：新增 `cycleLeftReadyAt`（离开预备位时刻），计数要求距其 ≥ 600ms。

### 第三层 · 计数时刻自愈
- 若计数靠比例回正达成而绝对回正未达成（= 基线已不可达，被污染），
  立刻把 `standingBodyY` 重锚为当前高度；后续 READY 的 EMA 再缓慢精修。
  打破死锁，下一拜立即恢复正常。

### 不变
- 底部阶段超时仍 ×5（合法长停留保护；卡死已由二三层解决）。
- 状态机骨架、参数面板、手动校准均不动。

## 常量
JUMP_REJECT_THRESHOLD=0.22；JUMP_CONSISTENCY_BAND=0.1；JUMP_ACCEPT_FRAMES=3；
SCALE_REJECT_LOW=0.55；SCALE_REJECT_HIGH=1.8；SCALE_ACCEPT_FRAMES=8；
MIN_BODY_SCALE=0.05；RECOVERY_FRACTION=0.7；MIN_CYCLE_MS=600。

## 验证
- 测试改为线性渐变（ramp）喂帧，贴近真实运动（瞬移帧本就该被滤掉）。
- 新增回归测试：单帧瞬移被剔除；持续新位置 3 帧后被接受；肩宽塌缩被拒收；
  **基线被污染后，当拜与下一拜都正常计数且基线自愈**。
- `npm run lint`、`npm test` 全绿后真机夜间复测。
